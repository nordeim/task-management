# AGENTS.md

Instructions for AI coding agents working in this repository. Every line answers: "would you get this wrong without being told?" Verified against the toolchain on 2026-09-15.

## Commands

Run from the repo root. **Bun** is the package manager (`bun.lock` is committed) — never mix npm/yarn installs.

| Command | What it does |
|---|---|
| `bun install` | Install dependencies |
| `bun run db:push` | Create/migrate `./db/custom.db` from `prisma/schema.prisma` (SQLite) |
| `bun run db:seed` | Idempotent seed via `scripts/seed.ts` — demo account + 4 boards + 25 tasks; safe to re-run |
| `bun run dev` | Dev server on :3000 (Turbopack) |
| `bun run lint` | ESLint 9 flat config (`eslint-config-next` defaults, **zero rule weakening**) — must exit 0 before pushing |
| `bun run typecheck` | `tsc --noEmit` — must report no errors; `skills/` and `docs/` are excluded from the compile |
| `bun run test` | Vitest unit suite over the pure domain seams — red first, then implement |
| `bun run build` | Standalone production build (also copies static assets into `.next/standalone`) |
| `bun run start` | Serve the standalone build on :3000 |
| `cat /secure/key \| python3 docs/ssh_git_wrapper_v3.py --key-stdin --remote git@github.com:nordeim/task-management.git` | The only sanctioned push path (see `docs/how-to-git-push-using-ssh-wrapper_SKILL.md`) |

Order for a clean check: `bun run lint && bun run typecheck && bun run test`. After schema edits: `bun run db:push` (then re-seed if you wiped the DB). `DATABASE_URL` must be set (`.env`, from `.env.example`) or every Prisma call fails at import time. The `skills/` folder is the owner's vendored skill library — it is excluded from lint, typecheck, tests, and build; never let it into a gate.

## Architecture invariants

- **Real URL routes mirror the reference.** `/` (dashboard), `/Boards`, `/Board?id=`, `/Analytics`, `/login`, plus a server-rendered `[...path]` catch-all that renders the styled slate 404. Authed surfaces live in the `(app)` route group whose layout (`src/app/(app)/layout.tsx`) mounts `AppShell` — it boots `/api/auth/me` and redirects logged-out users to `/login?from_url=<original>` (open-redirect-guarded in `routes/login-route.tsx`). Login and the 404 render bare, OUTSIDE the shell (the reference shows the login form even when authed). Capitalized spellings (`/Dashboard`, `/Boards`, `/Board`, `/Analytics`) rewrite to the lowercase routes in `next.config.ts` — paths are case-insensitive like the reference. Board sub-views (table/kanban/calendar/timeline/unassigned) are CLIENT state: the URL never changes, matching the reference. `navigate()` in `app-context.tsx` pushes real paths; the active view is DERIVED from the pathname (lowercased compare) so back/forward and deep links always land correctly.
- **All mutations return the `ActionResult<T>` envelope** (`{ ok: true, data } | { ok: false, error }`, defined in `src/lib/domain.ts`). Route handlers never throw across the boundary; the client (`src/lib/api-client.ts`) never parses throws. New endpoints follow the same contract.
- **`status` ↔ `completed` are one fact in two columns.** The coupling is the exported `resolveStatusCompletedPatch` in `src/lib/domain.ts`; the server applies it in `PATCH /api/tasks/[id]` and the client mirrors it in `board-view.tsx` after confirmation. If you write a new mutation path (bulk edit, import, automation), call the same function or the table checkbox, kanban, and analytics will disagree.
- **Every API input is Zod-parsed** (`loginSchema`, `createBoardSchema`, `updateTaskSchema`, …). Reject with a 400 + human-readable message from `parsed.error.issues[0]`; never fall back to raw `body as T`.
- **Pure logic lives in `src/lib/domain.ts` and is unit-tested** (`src/lib/domain.test.ts`). New logic follows TDD: failing test first, then the implementation. The status↔completed coupling is ONE exported function (`resolveStatusCompletedPatch`) consumed by both the PATCH handler and the client mirror — new mutation paths must call it instead of re-deriving the coupling. The board toolbar pipeline (search + people + status/priority + sort) runs through the unit-tested seams `filterTasks`/`sortTasks`; `sortTasks` covers ALL seven reference fields (title, created, updated, priority, status, owner, dueDate) with nulls-last in both directions; people filtering is the multi-select `personIds` array; column hiding runs through `visibleColumns`; the group footer row through `groupSummary` (first-encounter order, 3-badge cap, `overflowCount`); the group header dots through `statusHeaderDots`; boards-card time through `relativeBoardTime`. Wire new toolbar behavior into those seams, not inline lambdas.
- **Auth is cookie+session-table.** scrypt hashes (`src/lib/auth.ts`), opaque 32-byte tokens in the httpOnly `tuesday_session` cookie, 30-day TTL, lazy expiry cleanup on read. Ownership checks are `findFirst({ where: { id, ownerId: user.id } })` — a missing row means 404, which is also the not-authorized answer (no existence leak).
- **Domain vocabulary is closed.** Statuses, priorities, the six board colors, the seven group colors (`GROUP_COLOR_OPTIONS` — the Add New Group swatches, adds Gray `#676879`), and board visibility (stored `private`/`public`, labeled Private/Shared — see `visibilityLabel`) are `const` arrays in `src/lib/domain.ts`. UI components and API validation both derive from them — never hardcode a status string in a component. The palette is the reference's monday-canonical set (statuses `#c4c4c4`/`#ffcb00`/`#00c875`/`#e2445c` with **white pill text on all four**; priorities `#787d80`/`#ffcb00`/`#fdab3d`/`#e2445c` rendered as tinted text badges via `priorityBadgeStyle` — 12.5% alpha bg + colored text at `font-normal`; board colors `#0073ea #00c875 #ffcb00 #e2445c #a25ddb #00d9ff`). Each **group owns its accent color** (`Group.color`, default Ocean Blue) driving the 4px border-left in the table — not the board color. Kanban card left borders are the fixed neutral `KANBAN_CARD_BORDER` `#E1E5F3`. The view-dropdown trigger shows short labels via `VIEW_TRIGGER_LABELS` ("Main table", "Kanban", "Calendar", "Timeline") while the menu lists the long ones. Completed task titles are never struck through (reference behavior).
- **The board toolbar renders only in the Main Table view** (reference behavior — Kanban/Calendar/Timeline/Unassigned show just their own headers). Filter state (status/priority sets, the `personIds` array, sort, hidden columns) lives in `board-view.tsx` and applies to every view's task list even though the controls are table-only. All five dropdowns (Person/Filter/Sort/Hide/Group by) are card-styled popover menus (`w-64`, `text-lg font-bold` title + X close) — the reference's `_Z`/`RZ`/`TZ`/`AZ`/`MZ` anatomy; the Person/Filter/Hide buttons carry blue `w-5 h-5` count badges, and the Sort trigger always reads just "Sort". The Sort menu toggles asc⇄desc with NO off state; the Person filter is multi-select over the board's distinct owners (`distinctOwnerNames`).
- **App chrome follows the reference exactly**: the app nav highlights the active route — `bg-[#E1E5F3] text-[#0073EA]` on an exact, case-sensitive `pathname === href` match (`isNavActive` in `domain.ts`; re-probed 2026-09-17 — reference drift, the old "no highlight" invariant is obsolete). `/` highlights nothing (Dashboard's href is `/Dashboard`), `/Boards` → My Boards, `/Board?id=` → nothing. Inactive links are `text-[#323338] hover:bg-[#F5F6F8] hover:text-[#0073EA]`. There is **no app footer**, and page containers put the padding OUTSIDE the `max-w-7xl` container (`p-6`/`p-4 md:p-8` wrapper → `mx-auto max-w-7xl` inner) so the container keeps the full 1280px. The shell is `flex min-h-screen flex-col bg-[#F5F6F8]` with `<main class="flex-1 overflow-x-hidden overflow-y-auto">` — but see the scroll quirk below: the BODY is what actually scrolls on tall content.
- **Board page chrome** (probed): `min-h-screen bg-[#F5F6F8] > max-w-full > [sticky top-0 z-20 gray wrapper pb-4 > sticky top-16 z-40 white bar border-b] + px-6 py-6 content`. The white header is ONE row: back arrow (real `/Boards` anchor wrapping an `h-9 w-9` button) + color tile + `[h1 title over sub-row]` left; Analytics/Integrate/Automate (`h-8 px-3 text-xs border-[#E1E5F3]` with colored hover borders) + avatar row right. Sub-row: constant-`Table2` trigger (`h-6 px-2 text-xs text-[#676879] hover:bg-[#E1E5F3]`) | favorite pill (`h-6`, unfavored `#676879`, favored `#ca8a04`) | `N items ▪ Saved …` meta in `text-[#A0A0A0]`. The blue `h-1` strip on the header is a **binary has-scrolled marker**: `scaleX(0)` at rest, full width once `window.scrollY >= 32` (threshold probed live). Toolbar: ONE left-packed row in the white `rounded-xl p-4` card — `[New Task (h-10 #0073EA) | search w-64 h-10 bg-[#F5F6F8] | Person | Filter | Sort | Hide | Group by (h-10 outline px-4 border-[#E1E5F3])]` — never `justify-between` the popover group.
- **Dashboard "Recent Activity" lists recently-updated TASKS** (title + `Sep 17, 1:36 AM` absolute time via `formatRecentTaskTime`, gray→slate clock tiles), not the Activity event log — `/api/dashboard` returns `recentTasks` (top 6 by `updatedAt`); the Activity table still records events for the audit trail. KPI cards are `group perspective-1000` gradient buttons (left-aligned text), side cards are `from-white via-white to-{indigo|purple|green}-50/30` gradient cards with `flex` headers (w-12 gradient icon tiles).

## Framework quirks (verified the hard way)

- **Tailwind v4 is CSS-first.** There is no `tailwind.config.js` (a leftover v3-style config was dead weight and was removed). Tokens live in `src/app/globals.css` under `@theme inline`; shadcn semantic tokens are literal hex in `:root`. Do not reintroduce a JS config.
- **`react-hooks/set-state-in-effect` is enforced.** Two compliant patterns are load-bearing in this codebase:
  1. **Data loading**: `load()` is a pure `() => api(...)`; the effect does `load().then(result => …setState)` with a `cancelled` flag in cleanup. Never call an async `load` that setStates internally.
  2. **Dialog forms**: form state lives in a component **inside `<DialogContent>`** — Radix unmounts closed dialogs, so every open starts from `useState` initializers. Never add a `useEffect(() => open && reset())` — lint blocks it.
- **`BoardView` is keyed by board id** in `routes/board-route.tsx` (`<BoardView key={id} boardId={id}>`, id from `useSearchParams`). Switching boards remounts the component — that is the view-state reset mechanism. If you lift state out of it, you re-introduce the reset problem it solves.
- **Turbopack dev cache corrupts** if config files change while the server runs (panic: "Failed to restore task data"). Fix: `pkill -f "next dev"; rm -rf .next` and restart. Do not "fix" source files when the error is a cache panic.
- **`next-env.d.ts` churns** between `dev` and `build` (the type-root reference flips between `.next/types` and `.next/dev/types`). Restore the committed state (`git checkout -- next-env.d.ts`) before committing — never bundle the churn into feature commits.
- **Next 16 async request APIs**: `cookies()`, `params`, `searchParams` are Promises — always `await`. Page files may export only the framework-known keys.
- **Prisma + SQLite**: relative `DATABASE_URL` resolves against `prisma/schema.prisma`, not the repo root — hence `file:../db/custom.db`. `db/*.db` is gitignored; the DB is always recreatable via `db:push` + `db:seed`.
- **ESLint `ignores`** cover sandbox-only directories (`refs/`, `examples/`, `skills/`, `mini-services/`, `tests/`, `.zscripts/`, `tool-results/`, `upload/`, `download/`, `Caddyfile`). Those exist in the dev sandbox, not in a fresh clone — keep the list when editing `eslint.config.mjs`, or lint suddenly reports thousands of errors from vendored skill scripts.

## Money-sharp edges in this domain

- Due dates are stored at **local noon** (`date-cell.tsx` converts the native date input's value to 12:00 before `toISOString`) so timezone edges never shift the rendered day. Keep that when adding date inputs. The timeline's day columns rely on the same noon-stable comparison. The DateCell set-state renders plain `Sep 22` text (no calendar icon; icon only in the empty "Set date" state) and past dates become red-tinted chips (`bg-[#E2445C]/10 text-[#E2445C]`).
- Group collapse is **optimistic** (`toggleCollapse` patches UI first, reverts on API failure). New optimistic paths must have the same revert-on-failure shape.
- The analytics `days` window bounds tasks by `updatedAt`; **board performance deliberately ignores the window** (a board isn't "inactive" because nothing was edited). Preserve that asymmetry — it mirrors the reference product.
- `boards/route.ts` aggregates task counts with ONE grouped query + in-memory join, not per-board queries. Keep it that way as boards grow.
- Kanban drag IDs are namespaced (`status:<value>`, `person:<id|unassigned>`) so the same DnD context serves both groupings; parse the prefix in `onDragEnd`.
- **The scroll container is a LIE (probed live).** `<main>` carries `overflow-y-auto`, but every page root sets `min-h-screen`, so main grows with its content and the BODY is the element that actually scrolls on tall pages — main's `scrollTop` stays 0. Consequences: (1) window-scroll listeners (the board header's blue strip) are the correct pattern, NOT main-scroll listeners; (2) the nested `sticky top-16` wrappers are inert against main but still work against the body scroll — the nav pins (`sticky top-0 z-50`), the gray wrapper and white bar scroll away exactly like the reference. Verify any new sticky/scroll behavior with a forced-tall test (`zone.style.minHeight = '2000px'`), not with the seeded data (which fits the viewport).
- **SQLite file location quirk**: `DATABASE_URL=file:../db/custom.db` has been observed to resolve against the process CWD in some runs — the live file may land OUTSIDE the repo (sessions 3–5 all found it at `<parent>/db/custom.db`). If `db:seed` reports boards that `ls db/` says don't exist, check the parent directory. Also: **never delete the DB file while `next dev` is running** — the server keeps the deleted inode and every mutation fails with SQLite 1032 "readonly database"; restart the server after any DB file swap.
- Kanban column headers and priority badges use the same tint recipe (`${color}20` 8-digit hex = 12.5% alpha) — keep the kanban count badges and `priorityBadgeStyle` in sync if the recipe ever changes. The reference's kanban card OWNER avatar is an 8-gradient palette indexed by `name.charCodeAt(0) % 8` (`avatarGradient`) with `substring(0,2)` initials (`avatarInitials`) — NOT the table's solid-blue first-letter circle. People columns list only owners who own tasks (first-encounter `distinctOwnerNames`, `PEOPLE_COLUMN_PALETTE` badges); the Unassigned column renders only when non-empty and its empty-hint reads "Drag unassigned tasks here". Drag states: card `ring-4 ring-blue-200 scale-105` + white→#f8faff fill; drag-over column `scale-105 shadow-2xl` + its own `${color}20→${color}10` gradient.
- The reference's OwnerCell is FREE TEXT (decompiled `hZ`): a bare inline input on click (commit blur/Enter, Escape cancels), a solid-blue 24px first-letter avatar when assigned. The clone resolves typed names to member accounts (`ownerId` is a real relation); unmatched input keeps the previous owner — never invent users. The same free-text field lives in the Edit Task modal. The group header renders per-status count dots in FIRST-ENCOUNTER order (`statusHeaderDots`), and the footer's priority badges cap at three with a `+N` overflow — both reference quirks probed with 10 seeded tasks.
- The timeline grid math (`timelineRange`) is a pure, unit-tested function in `domain.ts` — week windows start Monday, month windows span calendar days. Change the grid, change the tests first. Reference timeline chrome (probed 2026-09-17): the zoom is a NATIVE `<select>` in a `gap-1` toolbar, month-mode columns are a fixed ~171.43px, day cells always stack weekday-over-number with `border-r` on every column, and the day-header row renders even with zero scheduled tasks. **The reference's timeline bars never render on current boards** — its bar component reads a literal `data.startDate` key that no current column model produces (verified live with 10 dated tasks; our due-date bars are a deliberate deviation).
- The calendar day grid lives INSIDE the card's single `p-4` zone (after the month row and weekday row) and its container carries `grid-rows-5 gap-px` — the 1px gaps show the card's white background between each cell pair's borders, producing the reference's double-hairline grid lines. Moving the grid outside `p-4` or dropping `gap-px` silently breaks the geometry (grid too wide, solid 2px lines). Calendar chips are PLAIN WHITE (the reference's priority-dot code is dead — no priority-type columns exist); clicking one opens the Edit Task modal.
- `TaskDTO` carries **both** `createdAt` and `updatedAt` — the Sort popover offers Created Date / Updated Date and both must round-trip from `toTaskDTO` in `boards/[id]/route.ts` (Prisma returns them by default; just map them).
- The board table is a **flex + sticky reimplementation of the reference sheet**: one white card holds every group zone, each zone scrolls horizontally (rows `min-width` from `rowMinWidth` via `COLUMN_WIDTHS`), with sticky rails (handle 24px left:0, checkbox 32px left:24, Task 250px left:56, action 50px right) and a sticky column-header band. Column pixel widths live in `COLUMN_WIDTHS`; adding a column means updating that map + the Hide popover's `COLUMN_KEYS` + `domain.ts`'s `ALL_COLUMNS`.

## Conventions that differ from defaults

- No `console.log` in shipped code (`console.error` with context is allowed on caught failures); the Prisma client logs `warn`/`error` only.
- Untested claims are labeled. When you verify behavior, say what you ran; when you couldn't, say that.
- Conventional Commits, atomic scope (`feat(board): …`). Never commit `.env`, `db/*.db`, logs, or the SSH key — `.gitignore` enforces the first three; the key must never enter the tree at all (rotate if it ever does).
- Buttons that depend on unconfigured integrations (Google OAuth, password reset, Integrate, Automate) render **honest "not configured" messages** — never fake success or leave dead buttons. The one exception that mimics the reference: the boards-page **Filter** button is deliberately inert (the reference's opens nothing); the board-page toolbar Filter remains fully functional.
